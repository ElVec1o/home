Architecture

Stratum ships as three integrated pieces:

Component Role Interface
C++ Core Lock-free streaming primitives, dual backends (pure + AVX-512) C ABI, ctypes + numpy zero-copy
Rust Crate Idiomatic Rust bindings, mergeable summary serialization crates.io, native Rust types
Apache Arrow Persistence, distribution, time-window rollups without rescanning Virtual tables in any SQL engine (DuckDB, ClickHouse, Velox)

Key Insights

The Cross-Disciplinary Borrow That Worked

Noticing that "mergeable summary" from streaming-algorithms, "CRDT" from distributed-systems, and "commutative monoid" from algebra are all the same thing. Once seen, three separate operational properties (persistence, distribution, time-window rollups) collapse into one property.

Don't Fight the FFI Boundary

Python→C FFI has ~600 ns overhead per call. The right move was admitting it, building a parallel pure-Python backend using numpy.argpartition, and reserving the native backend for streams that care about per-event tail latency.

Composition Beats Invention

None of the four primitives are new. The interesting work was making them fit: same architectural shape, same API surface, same dual backend, same Arrow representation. The fit is the product.
